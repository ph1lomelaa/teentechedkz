# Сид для страницы «Заявки на доступ»

Создаёт 13 заявок (по сценарию на строку) и двух тестовых пользователей.
Всё помечено: email `@seed.teenteched.test`, имена с префиксом `[ТЕСТ]`.

## Быстрый старт

```bash
scripts/dev-seed.sh        # база tte_seed + сид + бэкенд :8099 + фронт :5173, всё в фоне
scripts/dev-seed-stop.sh   # остановить (только свои процессы, по pid-файлам в /tmp/tte-dev-seed)
```
Нужны запущенные Postgres и Redis (`brew services start postgresql@17 redis`). Скрипт
отказывается работать с любой базой, кроме `tte_seed` на localhost. Фронт при этом
собран с `VITE_LOCAL_API_PORT=8099` и показывает жёлтую плашку «ТЕСТОВАЯ БАЗА»; логи
лежат в `/tmp/tte-dev-seed-*.log`. Ручной запуск тремя командами — ниже.

### Изолированная среда в Docker (рабочие данные не затрагиваются)

```bash
scripts/seed-up.sh                  # проект tte-seed: свои Postgres (:55432), Redis, бэкенд :8099
VITE_LOCAL_API_PORT=8099 npm run dev --prefix frontend -- --host 127.0.0.1 --port 5173   # фронт на хосте
scripts/seed-down.sh [--purge]      # остановить (--purge удаляет и том тестовой базы)
```
Контейнеры `tte_seed_*`, том `tte-seed_seed_pgdata`, `.env` не подключается, внешние сервисы пустые, воркера нет.
Фронт тоже можно в Docker: `scripts/seed-up.sh --with-frontend` (порт 5173; тяжелее по памяти).
Если ваш фронт уже в Docker на :3000, он по-прежнему ходит на :8001 (рабочие данные) — для сида открывайте :5173.

## Запуск

Из корня репозитория. Адрес БД обязателен и должен быть локальным
(`127.0.0.1` / `localhost`), иначе скрипт выходит, ничего не записав. Из `.env`
адрес намеренно не берётся: там `ENVIRONMENT=production` и хост `postgres`.

```bash
export SEED_DATABASE_URL=postgresql+asyncpg://$(whoami)@127.0.0.1:5432/tte_seed
.venv/bin/python backend/scripts/seed_access_requests.py
```

Повторный запуск дублей не создаёт. Пересоздать с нуля (удаляются только
помеченные записи):

```bash
.venv/bin/python backend/scripts/seed_access_requests.py --reset
```

Пустую базу под сид можно завести так (на этой машине 5432 занимает Homebrew
Postgres, не контейнер):
`createdb -h 127.0.0.1 tte_seed`, затем `Base.metadata.create_all` или
`bootstrap_db`.

Поднимите бэкенд с `DATABASE_URL` на ту же базу и откройте «Заявки на доступ».

| Кто | Email | Пароль | Что увидит |
|---|---|---|---|
| Админ | admin@seed.teenteched.test | SeedAdmin#2026 | очередь и кнопки одобрения |

## Сценарии

Ожидаемая группа — по текущим правилам: «прикрепить» = ровно одна карточка по
телефону и она свободна; «кабинет занят» = телефон совпал, но кабинет есть;
«проверить» = совпало только ФИО или несколько карточек на один телефон;
«создать» = кандидатов нет.

| № | Сценарий | Группа |
|---|---|---|
| 1 | точный телефон, свободная карточка | прикрепить |
| 2 | `8 701 000 00 02` ↔ `+7 (701) 000-00-02` | прикрепить |
| 3 | очень длинное ФИО и email | прикрепить |
| 4 | карточка принадлежит тому же аккаунту, что и заявка | кабинет занят |
| 5 | чужой кабинет, `last_login_at` пуст | кабинет занят |
| 6 | чужой кабинет, вход 3 дня назад | кабинет занят |
| 7 | совпало только ФИО, у карточки есть кабинет | проверить |
| 8 | две карточки с одним телефоном | проверить |
| 9 | совпадений нет | создать |
| 10 | у заявки нет телефона | создать |
| 11 | заявка ментора (карточек у менторов нет, см. ниже) | ментор |
| 12 | каз. буквы в заявке, латиница в карточке | проверить |
| 13 | латиница в заявке, каз. буквы в карточке | проверить |

Сценарий 11: у менторов нет «карточек» — это просто `User`. Поиск кандидатов
работает только для заявок на ученика, поэтому «свободную карточку ментора»
создать нельзя; заявка ментора идёт по ветке «Одобрить как ментора».
