# Год набора, завершение работы и синхронизация — 14.10.2026

Проверены код main и флаги рабочего backend; конкретные карточки из жалобы не названы.

Подтверждено:

- `intake_year` хранит год поступления/набора, не отдельный период сопровождения. Сервер разрешал его менять, но основная форма не предлагала это поле; рабочий кабинет показывал год только для чтения.
- Статус процесса хранится в последнем договоре. Значения `completed_admitted` и `changed_mind` уже означают завершение работы, не удаление карточки.
- API карточки не возвращал верхнеуровневый `pipeline_status`; список возвращал. Договоры карточки не были упорядочены, хотя интерфейсы использовали первый.
- Общая база и её группировка предпочитали статус Notion статусу CRM. Фильтр «Требуется назначение» ориентировался на Notion. Ручное завершение в CRM могло выглядеть неэффективным.
- Массовое создание карточек из анкет исключало архив из поиска совпадений. Повторная анкета архивного ученика могла породить новую активную карточку.
- Обычная синхронизация Notion обновляет зеркало и привязки, сама карточки CRM не создаёт.
- На момент проверки `ENABLE_INTAKE_AUTO_CREATE`, `ENABLE_INTAKE_AUTO_LINK`, `ENABLE_NOTION_FIELD_SYNC` выключены; режим записи Notion — dry run. Поэтому текущая жалоба на автоматическое появление не привязана к доказанному событию создания.

Исправлено:

- Общий редактор года и статуса в профиле CRM и рабочего кабинета. Сохранение одним PATCH, аудит изменений, серверная проверка прав, обновление кэшей обеих карточек и списков.
- Отдельное право `student_work_status:edit` для сотрудников, включая менторов, без выдачи права менять финансовые поля договора. Для смены требуется также право редактировать ученика.
- Статус обновляет последний договор; если запись процесса отсутствует, создаётся запись без суммы/даты подписания, как в существующей сверке Notion. Карточка не архивируется. Строка ученика блокируется на время изменения.
- API карточки отдаёт статус последнего договора; договоры для интерфейса упорядочены по времени создания и ID. Связь contracts загружается заранее, включая ответ PATCH.
- В общей базе и группировке основной статус — CRM. Отличающийся статус Notion виден отдельно; исходные данные зеркала сохранены. «Требуется назначение» относится только к активной работе CRM.
- Поиск совпадений при массовом создании из анкет включает архив. Архивное совпадение требует ручной проверки, не восстанавливается автоматически.

Не установлено: какие именно ученики повторно появились, когда, были ли это новые ID или отображение в другом представлении. Для подтверждения эпизода нужны пример карточки и приблизительное время.

Проверки: полный набор backend и frontend, lint, production-сборка; отдельные сценарии смены года/завершения без архивации, отсутствующего договора, последнего статуса, прав, пустых значений и совпадения с архивом.


## Уточнение владельца: Notion — первичный источник, затем правки в обе стороны

Реализовано первое согласование по Notion для ФИО, телефона, ступени, года набора и статуса работы. Для каждого согласованного поля сохраняется отметка и общий эталон. После этого одно изменённое значение переносится в противоположный источник; две разные правки сохраняются как конфликт. Явная новая правка сотрудника фиксируется транзакционно в очереди, поэтому первый синк не стирает её как старое расхождение.

Статус поддержан в проверяемом исполнителе и ручном разрешении конфликтов. Запись использует реальные опции поля «Статус выплат», включая окончания «Передумали»/«Поступил»; «Нет статуса» очищает select. CRM-изменения обрабатываются отдельным циклом очереди раз в 15 секунд. Частота чтения Notion настраивается отдельно. Архивные ученики и неоднозначные связи исключены из автоматического изменения.

Рабочая схема Notion прочитана: Intake/select, Статус выплат/select, Degree/select, Номер тел/phone_number. Найдено 408 связанных страниц и 11 групп с несколькими страницами на одного ученика; выбор источника для них не делается автоматически.

Доска распределения теперь использует тот же текущий статус, что карточка и общая база, и отдельно показывает несогласованный Notion. Счётчики статусов используют только последний договор. Защита архива добавлена также в создание одной карточки из анкеты.

Проверены оба направления и конфликт на настоящей временной PostgreSQL-базе с имитацией Notion API; схема теста удалена после проверки. Это проверка очереди и транзакций, не доказательство реальной записи в Notion. Для рабочего включения требуется проверка очереди с живым Notion в dry-run и последующий контроль записи/чтения.
